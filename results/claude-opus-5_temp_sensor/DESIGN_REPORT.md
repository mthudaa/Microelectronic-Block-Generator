# Self-starting relaxation-oscillator temperature sensor — GF180MCU `gf180mcuD`

**Cell** `temp_sensor` · **Ports** `VDD VSS TEMP_OUT` · **Model** `claude-opus-5`
· **Flow** `/mbg-full-auto` · **Result** `SUCCESS` / `TAPEOUT_READY`

---

## 1. What was asked and what was built

A temperature sensor whose *output frequency is the measurement*. Unlike a
clock reference, drift with temperature here is the signal, so the design goal
is a large, smooth, monotonic `f(T)` — not a flat one.

```spice
.subckt temp_sensor VDD VSS TEMP_OUT
```

No `CLK`, `START`, `ENABLE`, `RESET`, `IBIAS`, `VBIAS` or `TRIM` pin. No
external reference current. No forced initial condition anywhere in the
acceptance simulation. Flat single `.subckt`: **18 MOSFETs + 2 native
passives, 12 nets**.

### Topology

```
        VDD ──┬─────────┬──────────┬────────────┬─────────────┬────────┐
              │         │          │            │             │        │
            [XMP1]    [XMP2]    [XMS1]       [XMPC]      6T Schmitt   [XMB1]
          mirror 1:1  diode     weak          I_chg      trigger      buffer
              │      (nbp)      start          │       (XMSP1..3,       │
              ├─ nb1 ─┤          │             ├── ncap  XMSN1..3) ──nst┤
              │       │        [XMS3]          │            │           │
            [XMN1]  [XMN2]     kick         [XC1] 34x34um   │        [XMB2]
             1x      4x          │           MIM 2.33pF     │           │
              │       │        [XMS2]          │            │      TEMP_OUT
              │     [XR1]      shut-off      [XMNS] switch   │           │
              │    ppolyf_u      │             │             │           │
              │    1x100um       │          [XMNC] 2*I       │           │
        VSS ──┴───────┴──────────┴─────────────┴─────────────┴───────────┘
                                                  TEMP_OUT drives XMNS (loop)
```

1. **Beta-multiplier (constant-gm) current reference**, degenerated by a
   native `ppolyf_u` poly resistor (1 µm × 100 µm ≈ 37 kΩ).
2. **Self-extinguishing starter** `XMS1/XMS2/XMS3` — no external pulse.
3. **Native-passive timing core** — a metal4/metal5 `cap_mim_2f0_m4m5_noshield`
   MIM (34 µm × 34 µm ≈ 2.33 pF) ramped by the reference current.
4. **6-transistor CMOS Schmitt trigger** as the hysteresis comparator.
5. **CMOS inverter buffer** driving `TEMP_OUT` rail-to-rail and closing the
   loop onto the discharge switch.

Governing relation:

```
f  =  I / (2 · C · ΔV_hyst)
I  =  2 (1 − 1/√K)² / ( µn Cox (W/L)_XMN1 · R² )
```

## 2. Where the temperature coefficient comes from

This is the part of the design that was actually *engineered*, and it is worth
being explicit about, because the first working circuit missed the target.

The GF180 `ppolyf_u` resistor is almost temperature-flat — the model gives
`r_tc1 = −0.9e−4`, `r_tc2 = 7e−7`, which is **under 1 % across −40…125 °C**.
With `R` and `C` both effectively constant, the temperature coefficient of `f`
is carried almost entirely by **mobility**: the model's `ute = −1.5675` for
`nfet_03v3` means `µn ∝ T^−1.568`, so `1/µn` contributes about
**+5200 ppm/°C**.

That upper bound is only reached if `XMN1` is in **strong inversion**. The
first sizing (`W/L = 2 µm / 2 µm`, ≈ 2.5 µA, overdrive ≈ 0.14 V) sat in
*moderate* inversion, where the beta-multiplier degenerates toward the weak
inversion result `I = n·V_T·ln(K)/R`, whose coefficient is only `1/T`
≈ +3300 ppm/°C — and measured **+1725 ppm/°C** end to end, below the 2000 ppm/°C
floor.

Decomposing the measured waveform separated the two terms cleanly:

| term | −40 °C | +27 °C | +125 °C | implied coefficient |
|---|---:|---:|---:|---|
| ramp slope `I/C` | 2.287 V/µs | 2.773 V/µs | 3.513 V/µs | **+2600 ppm/°C** |
| Schmitt window `ΔV` | 1.663 V | 1.709 V | 1.794 V | +460 ppm/°C (works against `f`) |

So the current, not the comparator, was the limiting term. Widening or
narrowing the Schmitt feedback ratio moved the total by less than
±200 ppm/°C (measured at ratios 0.7, 1.0, 1.5, 2.0 — TC stayed between
+1517 and +1725 ppm/°C), which ruled that knob out.

The fix was to **raise the current density in `XMN1`** — `W/L` from 1.0 down
to 0.25 (`W = 1 µm`, `L = 4 µm`), which raises `I` to ≈ 9 µA at an overdrive
of ≈ 0.7 V — and then restore the frequency with capacitance rather than with
resistance, because raising `R` would have pushed the reference back toward
moderate inversion and undone the gain. Result: **+3949 ppm/°C pre-layout,
+3868 ppm/°C post-layout**, comfortably inside the 2000–6000 ppm/°C window
with margin on both sides.

## 3. Self-start, and why the acceptance simulation is honest

A beta-multiplier has a stable zero-current state. `XMS1` (a near-minimum
PMOS, `W = 0.6 µm`, `L = 9.5 µm`) holds `nsu` high while the bias is dead;
`XMS3` then pulls the PMOS mirror gate `nbp` down and current begins. Once
`nb1` has risen, `XMS2` clamps `nsu` low and `XMS3` switches off. Measured
steady-state `nsu` = **2.9 mV**, so the starter perturbs neither mirror ratio
once running, and its only cost is the ≈ 6 µA static current of `XMS1`.

**The acceptance simulation deliberately does not start from a DC operating
point.** A plain `tran` solves the DC operating point first and hands the
circuit its settled bias for free — which for this topology would have made
the start-up test vacuous, because ngspice converges straight to the running
solution. Instead every simulation in this report uses:

```spice
Vsup VDD 0 PWL(0 0 1u 3.3)     * modelled power-up ramp
...
tran <step> <stop> uic          * every node starts at 0 V
```

There is no `.ic`, no `.nodeset`, and no source on any signal node anywhere in
the deck. `uic` with no initial conditions declared is the *least* favourable
starting state, not a forced one: the circuit is fully de-energised and has to
bring itself up. Measured start-up (first `TEMP_OUT` rise through 0.9·VDD)
is **1.02–1.44 µs**, i.e. right after the supply ramp completes, against a
10 µs limit.

## 7. PVT characterisation — the F(T) curve

and the extracted netlist. Every point is an independent transient from a
0 V power-up ramp; the stop time is set from a measured probe run so that each
window really contains ≥ 100 cycles rather than an assumed number.

Process corners move **all three device classes**, not just the MOSFETs —
which matters more here than the transistor skew, because `I ∝ 1/R²` and

about **−7 %**, because the beta-multiplier reference is supply-independent to
first order and only the Schmitt window tracks the rail.

## 9. Residual risk

1. **Mismatch was not simulated.** The beta-multiplier's accuracy depends on
   the `XMP1`/`XMP2` and `XMN1`/`XMN2` pairs matching, and the duty cycle
   depends on the `XMN1`/`XMNC` 1:2 ratio. Random mismatch shifts the absolute
   frequency and the duty cycle. It does *not* plausibly break monotonicity —
   that comes from `µn(T)`, which mismatch does not change sign on — but the
   claim is untested and should not be made.
2. **Absolute frequency is uncalibrated and process-dependent by design.**
   Across `ss`…`ff` the 27 °C frequency spans roughly 2.5:1, dominated by the
   ±20 % poly-resistor sheet spread entering as `1/R²`. That is inherent to a
   single-point-uncalibrated sensor and is why the specification asks for the
   *sensitivity*, not a frequency accuracy.
3. **Current-source headroom at 3.0 V.** The ramp swings to ≈ 2.5 V, leaving
   `XMPC` about 0.5 V of `V_DS` at the low supply. Measured behaviour at 3.0 V
   is clean, but this is the node that would degrade first if the Schmitt
   window widened over process.
4. **The 34 µm MIM and the 100 µm poly resistor dominate the die area** and
   make the floorplan very heterogeneous (a 34 µm square next to 0.6 µm
   transistors). The placer handled it, but it is the structural feature most
   likely to trouble a future re-run at different sizes.

## 10. Framework changes this design required

The prompt named native passives as "a required stress point for the
framework's native-passive support". Two real gaps surfaced, both now fixed
and both reproduced from first principles rather than worked around:

### 10.1 LVS: the poly resistor's substrate pin

Magic extracts `ppolyf_u` with **three** terminals — the two resistor ends
plus the p-substrate. A schematic declaring only two makes netgen invent a
proxy net, and LVS fails on net count (12 vs 13) even though all 20 devices
match. Declaring the third terminal on `VSS` fixes LVS, but then MBG's
internal connectivity checker reported `missing_access: XR1.body (net VSS)` —
because `mbg.passives.poly_resistor` builds no substrate contact and exposes
no port for one. The connection is made by the p-substrate itself, held at
ground by neighbouring devices' substrate taps, which is exactly how Magic
extracts it. No router could ever satisfy that demand.

**Fix** (`src/mbg/connectivity.py`): `compare_with_netlist()` no longer
requires a routed access point for the bulk terminal of a `res`/`cap`
primitive **when that terminal is on the ground net**. A passive whose bulk
sits on any other net needs an isolating well and a real contact, and is still
reported. Regression: `tests/test_all_designs.py` — **8/8 designs pass all
four legs** after the change.

### 10.2 PEX simulation: `.option scale` does not reach subcircuit parameters

Magic's PEX netlist writes geometry in internal units with `.option scale=5n`
at the top. ngspice's `scale` applies to *device* geometry, so the transistors
inside `pfet_03v3`/`nfet_03v3` come out correct — but `c_width`/`c_length` are
plain **subcircuit parameters** feeding `.param c_area='c_length*c_width'`,
and ngspice never scales those. The extracted 34 µm MIM was therefore
evaluated as `c_width = 6800` **metres**, about 9×10⁴ F. The post-layout
netlist simulated as a completely dead circuit — timing node pinned at 10⁻¹⁶ V,
bias current correct at 9.4 µA — for a reason that had nothing to do with the
layout.

**Fix** (`ts_sim.py::_descale_passive_params`): rewrite only the passive
width/length parameters into explicit absolute units and leave `.option scale`
in place for the transistors. Post-layout frequency then lands within 4.7 % of
pre-layout, as it should.

### 10.3 Two more findings worth recording

* **`W = 0.22 µm` is not buildable.** glayout cannot fit a source/drain via
  array on the PDK-minimum width (`via_array,size:dim#1=0.28 < 0.46`) and the
  placer aborts with a `KeyError`. The practical floor is ≈ 0.4 µm; the
  starter device was widened to 0.6 µm.
* **ngspice `trtol` default corrupts supply-current measurement.** At the
  default `trtol=7`, local truncation error accumulated into the *voltage
  source branch current*: `i(Vsup)` drifted from 41 µA to 520 µA over 40 µs
  while every node voltage, the frequency and the duty cycle stayed correct —
  and the drift changed when unrelated vectors were added to `wrdata`. With
  `trtol=1` the measurement is stable in time and identical across those
  variants. Every current figure in this report was taken with the tightened
  options, and averages are time-weighted (trapezoidal), because ngspice
  clusters timepoints around the fast output edges where the crowbar current
  spikes.

### A note on the flattened model library

MOSFET models are read from `pdk_flat/sm141064.ngspice`, a copy of the PDK
model file with its ~1000 quoted parameter expressions pre-evaluated under the
nominal `sw_stat_global=0` / `sw_stat_mismatch=0` switches. The stock library
re-evaluates them at every Newton iteration, which makes a 250 µs transient
unusable. **Passives are read from the stock PDK in both cases** — the
resistor and MIM corner sections carry their own `.param` blocks
(`rsh_ppolyf_u`, `mim_corner_2p0ff`) that only the corner wrappers define, and
`.lib res` / `.lib cap_mim_new` alone make ngspice abort.

A speed-up that changes the answer is worthless, so `check_flat_lib.py`
re-derives the equivalence rather than asserting it: it runs the actual design
on both libraries and compares them. **Measured** (`flatlib_check.log`): at
−40, +27 and +125 °C, all 10 compared quantities — every internal bias node
(`nb1`, `nbp`, `nrs`, `nsu`, `ncap`, `nst`, `npa`, `nnb`, `nsk`) and the
supply current — agree to a maximum absolute difference of **0 V**, i.e. the
two libraries produce bit-identical operating points.

The script's transient half (`--tran`, comparing frequency, duty, swing,
start-up and average current at the same three temperatures) was **NOT RUN**
in this session — it is slow for exactly the reason the flattened library
exists, and the machine was busy with the PVT sweep. The bit-identical
operating points are the evidence offered here; the transient comparison
remains available.
